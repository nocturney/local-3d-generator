## Scope: actual restore rehearsal, not production package upgrade

G3.40 retrieved and verified the original official Pillow10.1.0 Windows cp311 rollback wheel and performed a real Pillow-only offline install/reinstall on an independent clean Python venv. G3.41 then made a complete private, SHA-audited production Python venv filesystem snapshot: **27,966 regular files / 5,086,619,721 bytes (4.74 GiB)**, with 34/34 installed versions and all 269 pinned CPU tests proven to work from the private snapshot itself.

G3.42 is a stronger independent checkpoint: it uses the PRIVATE G3.41 backed-up files as source and actually creates a SECOND full virtualenv in a new, randomly generated, disposable, independently owned QA path. It is not a copy of the LIVE production Python venv: the backup is the only restore input. The original production venv and original backup remain read-only.

## Full honest restore procedure

scripts/g3-42-restore-complete-venv-offline-cpu.py:

1. Verifies original G3.41 private snapshot manifest SHA256 and each of its 27,966 SHA-256 file records against the backup source, refusing extra/missing files, symlinks, reparsepoints or total-byte/count drift.
2. Verifies D: free disk space and launches a fresh TemporaryDirectory within private, gitignored LOCAL3D QA.
3. Copies the ENTIRE virtualenv directory, including Windows Python venv launcher, pip/package dist-info metadata, native C/C++ libraries and all 34 pinned distributions, from the backup into the brand-new owned restore path.
4. SHA-checks **every one of the 27,966 restored files** independently against original private manifest and checks there are zero unexpected/missing paths.
5. Starts Windows Python3.11 from the RESTORED path, verifying its sys.prefix, Pillow10.1.0 native import location, no original production venv import, 34/34 exact pinned distribution versions AND distribution locations under restore path, plus trusted original SHA-locked PNG/JPEG/WebP native RGB decoding.
6. With L3D_ENABLE_TRIPOSR=0, CUDA_VISIBLE_DEVICES=-1, HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1 and PYTHONDONTWRITEBYTECODE=1, executes all 262 G3 Python quality tests and all seven G2 offline unit tests from the restored interpreter — no model weights loaded or actual GPU inference.
7. Independently SHA-checks ALL restored file bytes again AFTER running the CPU tests, preventing silent write pollution or newly generated bytecode from being mistaken for a pristine restore.
8. Exits the TemporaryDirectory context and removes ONLY the disposable full restore (NOT the original backup, production interpreter, original offline Pillow wheel or customer data).
9. Records a small sanitized deterministic private CPU receipt under ignored runtime/qa/g3/g342-real-restored-full-venv-cpu-qa.json, with only aggregate counts, SHA, passes and negative security flags.

The independent backup snapshot already exists at runtime/qa/g3/venv-recovery/production-py311-pillow101-complete-packages. It remains on the same authorized D: drive; no external cloud service, remote backup, model weights or user records are included. The disposable RESTORE should not remain after this milestone.

scripts/g3-42-readonly-snapshot-drift.py is a separate bounded, read-only inventory check and earlier verified that the G3.41 snapshot retained exactly 27,966 listed files with **zero extra or missing files** even after 269 CPU tests were run directly from it.
