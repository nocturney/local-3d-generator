# LOCAL3D G3.27 — bounded PNG/JPEG/WebP container structure preflight (CPU contract)

2026-10-10 | v0.2.27-g3-bounded-image-structure-contract-cpu

## Objective and scope

The prior G3.26 experiment proved a short-signature/MIME matching request could be admitted by G1 DEMO despite an incomplete image. G3.27 implements a **standalone, off-path Node CPU-only strict container syntax contract**, not yet wired to either G1 or manual G2. It establishes a tested, bounded way to reject missing/suspicious container structures before later admission integration. It does **not** invoke Pillow, native codec decompression, unsafe image fuzzing, TripoSR, GPU, printer, cloud, network or OS security controls. It is NOT security clearance.

Implemented server/image-structure-preflight.js with pure bounded parsing of admitted formats:
- **PNG**: strict signature, IHDR first and exactly once, 13-byte IHDR, accepted color/bit-depth combinations, chunk envelope/order/limits, CRC32 per chunk, IDAT presence/contiguity, IEND exactly once and terminal, no trailing bytes, reject unknown critical chunk and color/palette inconsistency. No zlib decode of IDAT.
- **JPEG**: SOI, bounded marker/segment parsing, scan-aware byte stuffing/restart markers, SOF dimensions/components, SOS and EOI at exact end, rejects truncated segment/scans and trailers. No Huffman/IDCT decode and no native decoder.
- **WebP**: RIFF size exact, WEBP FourCC, bounded chunk-size/padding cursor, VP8 or VP8L frame dimension headers, optional VP8X extended canvas dimensions, rejects inconsistent chunk lengths and animation. No VP8/VP8L frame decode.
- Cross-format: declared MIME exactly matches detected format, buffers <=8MiB, width and height <=16,384 pixels each, total pixels <=16M, optional minimum side of 64 for later manual G2 alignment. Bounds cap PNG chunk visits (1024), JPEG marker visits (4096) and WebP chunk visits (256). Any uncertainty throws BAD_IMAGE_STRUCTURE without producing an admission decision.

**Critical distinction:** this is a CONSERVATIVE structural validator. Some unusual technically valid images or animated WebP may be rejected when enabled; accepting a file would not establish that Pillow decodes it or that native parsing is secure. OS-enforced parser confinement, outbound network restrictions and full vulnerability triage Issue #4 remain OPEN.

## Existing historical evidence kept immutable

G3.25 and G3.26 reports are unchanged and still describe the historical source bytes. G3.27's proof binds the already-public G3.26 immutable report SHA to current source, new parser and THREE original in-memory-generated 64x64 trusted Pillow images. All 3 valid PNG/JPEG/WebP originals passed; 18 synthetically truncated variants (6 per format) rejected. Additional adversarial CPU tests cover MIME/unknown formats, PNG CRC/tampering/chunk bounds, oversized dimensions, JPEG missing EOI/malformed markers, WebP RIFF/trailer/format invalid, and size limits.

This G3.27 code **does not change server/index.js**. It therefore intentionally does NOT fix current G1 short-header-only HTTP admission yet and cannot claim active G2 runtime hardening. Separate G3.28 integration must preserve the G3.25/G3.26/G3.27 immutable historical SHA chain and update associated test expectations without ever rewriting old proof JSONs.
