# LOCAL3D G3.26 — harmless synthetic image-format boundary probes (CPU)

2026-10-10 | v0.2.26-g3-safe-image-signature-boundary-cpu

## Purpose

Continue G3.25 security Issue #4 WITHOUT parsing any untrusted files, running a GPU model, changing OS settings or upgrading Pillow. The G3.25 source review showed the Node image admission check uses ONLY a short PNG/JPEG/WebP signature plus caller-declared MIME and 8 MiB length, whereas the later manual G2 worker uses Pillow to fully decode pixels. G3.26 independently evaluates the difference using ONLY in-memory programmatically generated images and harmless incomplete signatures.

This is an **admission-boundary diagnostic**, NOT proof of a vulnerability exploit, exhaustive codec safety, a patched runtime, a user-upload authorization or a manufacturing qualification.

## Focused observations actually measured on Chris

- Frozen Pillow version: **10.1.0**; WebP codec support available.
- Created THREE original 64x64 RGB images, wholly in memory using Pillow: PNG, JPEG, WebP. Each had a short header that matched its normal MIME, and **Pillow.Image.open + load decoded its own image format**. The raw encoded data remained transient in memory; public output contains only SHA256 and byte counts.
- All THREE **harmless intentionally incomplete header-only buffers** failed full Pillow decode. This is deliberately not fuzzing, malformed complex graphics or an attack-payload experiment.
- Separate TRUE LOCAL HTTP tests exercised the existing **G1 fixture/demo-only** /v1/jobs entrypoint. All THREE incomplete short-signature synthetic buffers were **admitted as 201 in DEMO mode**, despite being incomplete as images; mismatched declared MIME or arbitrary unknown prefix returned **422 BAD_IMAGE**. These inputs NEVER used the G2 manual provider and did not reach its decoder or GPU.
- This demonstrates a precise **difference between API signature recognition and full image validity**; it does NOT establish vulnerability exploitability. The G2 manual provider is gated and was not started/tested with these buffers.

## Implementation and provenance

- engines/quality/safe_image_fixture_probe.py has **no arbitrary path/file input** and no network. It creates 64x64 colored images as BytesIO, runs only Pillow CPU encoding/decoding on those trusted generated bytes and checks incomplete inert headers against an independent Python short-header diagnostic. The Python mimic is not represented as actual Node execution.
- scripts/g3-26-safe-image-boundary-proof.py binds a bounded immutable public evidence JSON to **exact G3.25 public proof SHA**, current tracked Node server and Python worker source SHA and newly tracked safe-probe source SHA. It fails closed if G3.25 safety flags/source lineage/Pillow version changes. Run once with --write-public, then no-flag read-only replay.
- tests/g326-harmless-format-api.test.js exercises the ACTUAL existing Node HTTP G1 fixture route on dynamic safe loopback test ports, confirming signature/MIME semantics without invoking G2; asserts the sanitized proof never authorizes untrusted parsing or printing.
- engines/quality/test_g326_safe_image_boundary.py adds 8 Python adversarial/positive controls for 3 generated good formats, rejection of alternate generation formats, header-only vs full decode, deterministic SHAs and source/approval drift.

Sources: [immutable CPU-only sanitized proof](evidence/g3/g3-26-harmless-image-boundary.json), [preceding G3.25 official-advisory review](G3_25_PILLOW_FORMAT_API_TRIAGE_CPU_2026-10-10.md).

## What the result DOES and DOES NOT say

A valid short file signature is neither full codec recognition nor full image decode nor OS isolation. The live manual-G2 worker's own Pillow image load, memory/file permissions, native codec transitive calls, limited size and error handling need separately scoped analysis, using **approved bounded trusted synthetic inputs and OS-backed containment** for any untrusted exposure. Merely adding more MIME/header checks does not independently establish native parser safety.

The observed HTTP 201 is limited to G1 DEMO; G1 source-image acceptance is not execution of actual TripoSR. G3.26 has not exercised a G2 malicious image or any real GPU path, has not proven an exploitable vulnerability, and has not upgraded the running Pillow 10.1.0.
